# 需求规格文档 v1.6
项目：要事图 / Yaoshitu —— 坐标系任务管理器
整理时间：2026-10-18
整理人：需求澄清助手

## 一句话描述
本地优先的多视图任务管理器，坐标系为旗舰视图，四象限矩阵/列表/仪表盘/智能视图并列；隐私优先、开源核心（Open Core），云同步为可选功能（当前版本不分付费免费）。

## 背景与问题
### 现状
已对两个艾森豪威尔矩阵参考实现完成深度分析：
- **GSD Task Manager**（Next.js Web PWA）：四象限离散模型、可选 PocketBase 云同步、矩阵/仪表盘/归档/智能视图/sync-history 多视图、文档/测试/AI 集成拉满、a11y 第一公民
- **Focus**（Flutter 原生）：四象限离散模型、完全离线、桌面系统集成深、隐私极致

### 痛点
1. **粒度粗**：两者均为「紧急?×重要?」布尔判定，任务只能落进四个格子，无法表达"紧急度 70 分、重要度 85 分"这种连续差异
2. **取舍两难**：GSD 重同步便利轻隐私（数据上云）；Focus 重隐私轻多设备（手动导数据）。用户两者都要
3. 现有工具形态单一（纯 Web 或纯原生），缺少"快速捕获"入口；视图单一

### 触发原因
构造一个替代品：连续坐标 + 本地优先 + 可选云同步 + 多形态（Web/插件）+ 多视图。

## 目标与成功标准
| 阶段 | 目标 | 成功标准 |

## 视图架构（信息架构）
**核心原则**：所有视图读写同一份本地数据（IndexedDB）。坐标系与象限矩阵是同一份坐标数据的两种投影（连续 vs 阈值二值化），不重复造数据。视图切换时保持当前任务上下文（选中/筛选）。

### 智能视图的梯度语义（我们的升级点）
GSD 智能视图基于布尔/依赖（如 "Ready to Work"=无阻塞依赖）。我们用连续坐标表达**梯度**：
- `🔥 热点`：紧急>75 且 重要>75 —— 真正该先做的
- `⏰ 即将逾期`：截止<3天 且 未完成
- `🤝 可委派`：重要<40 且 紧急>60
- `🗑️ 该消除`：紧急<40 且 重要<40
- `🏷️ 按标签` / `✅ 近期完成`（streak 来源）

（阈值 50/75/40/60 为初稿，待定；用户自建筛选规则留待后续版本，一期固定 5 个）

### 导航
左侧固定视图栏（图标+文字）+ 命令面板（Ctrl/Cmd+K）跳视图/新建/搜索；**默认视图 = 坐标系**（可在设置更改）。

## 功能需求

### Must Have（一期 MVP，纯本地、无需注册）
视图（详见"视图架构"章节，以下为能力声明）：
1. **坐标系视图**：连续坐标 + 拖拽调优先级（完全自由、无磁吸）+ pan/zoom + 点碰撞处理 + hover 信息卡 + 空白点击创建；四象限分区线**始终显示**；完成态任务点**移出坐标系**（仅列表可见）；递归任务**一个点代表整个系列**
2. **象限矩阵视图**：连续坐标阈值投影成四象限，跨象限拖拽=调坐标
3. **列表视图**：等价列表，键盘可达、读屏兼容（a11y 兜底），批量操作
4. **仪表盘 / 复盘**：完成趋势、象限分布、标签统计、streak
5. **智能视图**：一期实现 5 个（热点/即将逾期/可委派/该消除/按标签）
6. **工作方式模块**：纯笔记（标题/正文/标签/置顶），不与任务联动
7. **归档**：回收站(30 天) + 永久归档；删除支持撤销（结构性，非 toast 计时）
8. **任务 CRUD（UI 子集）**：标题、备注、截止日期、完成状态、标签、归档
9. **数据模型 schema 全量**：子任务、递归、时间追踪、依赖、提醒等字段一次建模，UI 分批上线（明示"已建模未出 UI"清单）
10. **本地 IndexedDB 存储**：唯一真相源，零外部请求；schema 升级用 Dexie versioning 不丢数据
11. **JSON 导入/导出**：版本化备份信封 + 备份提醒（"上次备份 N 天前"）
12. **触摸/移动端交互适配**：长按菜单 / 底部 sheet 替代 hover/拖拽；PWA 可安装到手机
13. **导航与默认视图**：左侧视图栏 + 命令面板；默认坐标系，可设置

### Should Have（二期）
1. **注册登录**：首版仅支持 GitHub OAuth，不提供邮箱密码注册、登录及密码重置；保留游客模式，登录与多设备同步一起交付。账号空间与游客空间分别隔离，首次登录后由用户选择是否将游客数据复制进账号；保留账户删除、个人数据导出/销毁。
2. **云同步（可选）**：自托管 PocketBase + SQLite（部署目标 Ubuntu，计划域名 `yaoshi.xyz`）；本地 IndexedDB 先写入，持久队列重放，字段级合并 + 服务端版本检查，SSE 只通知变更。不同字段修改互不覆盖；同字段采用服务器接受顺序的 LWW，并保留有限冲突旧值。坐标对与完成状态分别原子更新。任务全部状态、原则笔记和默认视图参与同步；设备状态不参与。软删除同步，服务器 30 天统一清理，永久保留不含任务内容的删除标记以防离线旧设备复活。同步层抽象接口，避免绑定具体 SDK。**当前版本不分付费/免费，付费分层留待后续版本**。
   **备份与加密**：独立保留完整 JSON（任务含归档/回收站、笔记含回收站、用户设置），排除账号凭据、队列和设备标识。账号空间仅合并导入，游客可选择覆盖恢复；合并生成新 ID 并重映射任务引用。服务器自动备份另存异地并演练恢复。HTTPS + 服务端静态加密，密钥独立保管；首版不做端到端加密。注销清理在线账号数据及当前浏览器账号空间，历史备份按保留周期过期。
3. **同步历史视图**：云同步记录与冲突日志
4. **浏览器插件**：快速捕获入口（选中文字 → 一键生成任务点），明确数据通道、跨浏览器同步
5. **分批 UI 上线**：子任务、递归、时间追踪、提醒（浏览器推送）、依赖
6. **深色模式**、快捷键（`n` 新建、`/` 搜索、`?` 帮助）
7. **测试 / CI 门禁**：开源项目质量基线（Vitest 单测 + 关键 E2E + CI 零警告门禁）

### Won't Have（明确不做）
- 团队协作、任务分享（与隐私定位冲突）
- 遥测/分析、数据用于训练
- 广告、订阅式收费（未来若收费也只做一次性高级功能解锁或订阅云服务，不做广告）
- 坐标系作为"唯一视图"——已用列表视图兜底 + 多视图架构，不做纯坐标系独占

## 非功能需求
- **性能**：坐标系 SVG 渲染（500 点规模原生命中/事件，开发简单）+ 虚拟化 + pan/zoom，500+ 任务 60fps；Canvas 留作上万点优化项；首屏 < 2s
- **安全**：一期零外部请求；二期传输 TLS、云端静态加密、OAuth token 安全存储；首版仅 GitHub OAuth，不维护用户密码
- **可用性 / 无障碍**：PWA 可安装、完全离线可用；a11y 基线 WCAG 2.1 AA；坐标系不依赖色相（四象限用颜色+位置双重编码）；列表视图为无障碍主通道
- **数据可移植**：导入/导出用户可控，Dexie versioning 迁移不丢数据
- **视图一致性**：切换视图保持当前任务上下文；坐标系与象限矩阵同源同步
- **开源合规**：Open Core 模式——核心开源（MIT）+ 云同步模块闭源

## 资源与约束
- 时间：MVP 4-6 周；二期视 MVP 反馈启动
- 技术栈：React 19 + TypeScript + Vite 8（Rolldown）；React Compiler（自动 memoization）；状态 Zustand；IndexedDB（Dexie + versioning）；坐标系 SVG 优先（Canvas 为大数据量优化项）
- 后端（二期）：自托管 PocketBase（单 Go 二进制 + SQLite，OAuth/实时订阅；业务内容静态加密由应用扩展实现）。Ubuntu 部署，计划使用 `yaoshi.xyz`，HTTPS 入口统一代理网页和同步 API。
- 工程：TDD + CI 门禁
- 本地化：一期仅中文（多语言留待后续版本）
- 人力：单人
